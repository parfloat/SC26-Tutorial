\begin{frame}{Algorithm: LU with partial pivoting, solve $Ax=b$}
\small
\[
PA=LU,\qquad
\underbrace{p=\arg\max_{i\ge k}|U_{ik}|}_{\text{pivot}},\quad
\underbrace{L_{jk}=\tfrac{U_{jk}}{U_{kk}}}_{\text{multiplier}},\quad
\underbrace{U_{jl}\mathrel{-}=L_{jk}U_{kl}}_{\text{eliminate},\ j>k,\ l\ge k}
\]
\[
Ly=Pb\ \ (\text{forward}),\qquad Ux=y\ \ (\text{backward})
\]
\centering

\begin{frame}[fragile]{The defensive fix: snap tiny values to zero}
\begin{semiverbatim}\footnotesize
val = U[j][l] - L[j][k] * U[k][l];
if (fabs(val) < 10.0 * DBL_EPSILON)   // 2.2e-15
    val = 0.0;     // set to zero if close to machine epsilon
U[j][l] = val;
\end{semiverbatim}
{\tiny in \texttt{eliminate\_kernel} (\texttt{lu\_solve\_gpu.cu}, lines 210--211)}

\vspace{3mm}\centering
\begin{tikzpicture}[node distance=5mm]
  \node[graybox, text width=2.2cm] (b1) {pivot candidate\\6.9e-17};
  \node[bluebox, right=of b1, text width=2.4cm] (b2) {$|val| < 2.2\text{e-}15$\\$\Rightarrow val = 0.0$};
  \node[graybox, right=of b2, text width=2.2cm] (b3) {pivot is exactly\\0.0};
  \node[bluebox, right=of b3, text width=3.6cm] (b4) {\texttt{compute\_multipliers}\\$L = U / 0.0 \Rightarrow \pm$Inf};
  \node[redbox, right=of b4, text width=2.2cm] (b5) {Inf, then NaN\\through the solve};
  \foreach \u/\v in {b1/b2,b2/b3,b3/b4,b4/b5} \draw[flowarrow] (\u) -- (\v);
\end{tikzpicture}

\vspace{3mm}\raggedright\small
\begin{itemize}
\item Intent: remove round-off noise, keep zeros exact, make a singular matrix visible.
\item Effect here: ``inaccurate'' (residual 33.9) becomes ``divide by zero'', and the failure is now apparent.
\item The clamp's threshold is absolute (2.2e-15), whatever the scale of the matrix.
\end{itemize}
\end{frame}

\begin{frame}{Binary instrumentation reveals exceptions you did not expect}
\small
\begin{itemize}
\item The source computes only in double, yet \texttt{bad\_matrix.csv} also reports 6 FP32 NaN detections (93 repeats).
\item Cause: \texttt{ptxas} uses the idiom \texttt{FFMA R8, RZ, R5, R3} ($0\times$R5$+$R3 $=$ R3) as a register move, shuffling the 32-bit halves of a double. nixnan sees an f32 \texttt{FFMA} whose operand R5 decodes as NaN.
\item Lesson: a SASS-level detector reports what the compiled code does, not what the source says. A nonzero count in a format the source never uses is not necessarily that format's arithmetic.
\end{itemize}
\vspace{4mm}\centering
\begin{tikzpicture}[node distance=6mm]
  \node[graybox, text width=2.4cm] (d) {double\\64 bits = hi $|$ lo};
  \node[graybox, right=of d, text width=2.2cm] (r) {R5\\one 32-bit half};
  \node[bluebox, right=of r, text width=3.6cm] (f) {\texttt{FFMA R8, RZ, R5, R3}\\$0\times$R5$+$R3: a register move};
  \node[redbox, right=of f, text width=1.8cm] (g) {flagged\\f32 NaN};
  \foreach \u/\v in {d/r,r/f,f/g} \draw[flowarrow] (\u) -- (\v);
\end{tikzpicture}
\end{frame}

\vspace{3mm}\raggedright\footnotesize
\begin{itemize}
\item Without the clamp: finite wrong answers (residual 26--219) and nothing for nixnan to report, in both precisions and both sizes. With it: exact zero pivot, NaN, and nixnan counts the NaN, Inf and division by zero.
\item The well-conditioned matrices stay clean in every configuration (residual 1e-15 in FP64, 5e-7 in FP32; no exceptions).
\item $128{\times}128$ matrix: product of two perturbed tridiagonal bands, cond $\approx 3\times10^{17}$ (80-digit arithmetic; \texttt{gen\_matrix\_n.py}); \texttt{bad\_matrix.csv}: $\approx 2\times10^{17}$.
\item FP32 solves a rounded copy of the matrix. Its pivot at $128{\times}128$ (1.03e-6) sits just under the FP32 clamp threshold (1.19e-6): one seed, no claim about other matrices.
\end{itemize}
\end{frame}
